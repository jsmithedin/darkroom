# Darkroom

Self-hosted film photography tracker (replaces a Google Sheet). FastAPI + Postgres backend, React PWA frontend, authenticated MCP server at `/mcp`. Single user.

- Spec: `docs/superpowers/specs/2026-11-22-darkroom-design.md` (decisions, data model, auth)
- Plan: `docs/superpowers/plans/2026-11-22-darkroom.md` (task by task; each task is a GitHub issue)
- Findings from spikes: `docs/notes/`

## Commands

```
uv sync                                  # install
uv run pytest                            # tests (needs Docker: testcontainers starts Postgres 16)
uv run ruff check . && uv run ruff format --check .
uv run mypy backend/app
uv run alembic -c backend/alembic.ini upgrade head   # needs DATABASE_URL
uv run alembic -c backend/alembic.ini revision --autogenerate -m "msg"
```

## Dependencies

Anything imported by `backend/app` belongs in `dependencies`, not the `dev` group: tests install dev deps and will not catch a miss, but the Docker image (`uv sync --no-dev`) will crash on start. After adding imports, check with `docker build -t darkroom-check . && docker run --rm -e PYTHONPATH=/srv/backend darkroom-check python -c "import app.main"`.

## Layout

- `backend/app/` FastAPI app (`main.py` has `create_app(settings)`), `config.py` Settings, `db.py` engine and `get_session`
- `backend/tests/` pytest; `conftest.py` provides `db_session` (rolled back per test) and `client` fixtures
- `backend/alembic/` async migrations; `env.py` reads `Settings().database_url` unless the ini sets `sqlalchemy.url` (tests do). `models/__init__.py` must import every model so autogenerate sees it. `test_models_match_migrations` fails if models and migrations drift.
- `models/base.py`: `Base` (naming convention) and `AuditMixin` (id, timestamps, created_by/updated_by). Every table uses the mixin unless the spec says otherwise.
- `backend/app/mcp/server.py`: `build_mcp()` and Host/Origin settings derived from `PUBLIC_BASE_URL`. `create_app` mounts the MCP app at `/` **last** and enters `mcp.session_manager.run()` in its lifespan (FastAPI won't run the mount's lifespan). See `docs/notes/mcp-mount-spike.md` before touching this.
- `backend/app/spa.py`: `RootApp` is the final catch-all mount. Cache headers (#55): `/assets/*` is `immutable` for a year (Vite hashes the names), everything else from `dist` is `no-cache`. The serving and native-client decisions are in `docs/notes/frontend-serving-and-native-client.md`: keep serving from FastAPI, and **a native client cannot use OAuth yet** (OAuth tokens are bound to `/mcp` and refused on `/api`; custom-scheme redirects are refused). `/mcp` and `/.well-known` go to the MCP app; unknown `/api/*` is a JSON 404; other GETs serve `frontend/dist` with SPA fallback. New top-level public paths (`/auth`, `/oauth`) must be real FastAPI routes added before the mount.
- `frontend/`: Vite + React + TS + TanStack Query. **Vite 8 needs Node >= 20.19**; nvm's default here is 20.11, so use `/usr/bin/node` (v26) or `.nvmrc` (22). Commands: `npm run dev|build|typecheck|test` (Vitest + Testing Library, jsdom).
- Frontend auth (Task 1.3): `src/api/client.ts` `apiFetch<T>` is the only way to call the API: it sends the cookie, adds `X-CSRF-Token` on unsafe methods (fetched from `/api/me` and cached) and sends 401s to `/login`. Hooks in `src/api/hooks.ts` (`useMe`, `useTokens`, `useCreateToken`, `useRevokeToken`, `useLogout`). Routes in `src/App.tsx` (react-router); `AppShell` guards everything but `/login`. Tests mock `fetch` with `vi.stubGlobal` and call `setCsrfToken`/`setUnauthorizedHandler` to avoid real redirects. Reference data (Task 2.2): `src/api/reference.ts` (`REF_KINDS`, `useRefItems(kind, {includeArchived})`, create/update/archive hooks; query key `["ref", kind, includeArchived]`), `components/RefSelect.tsx` (**use this for every camera/lens/film/developer/filter/format dropdown**: hides archived items except the selected one), `components/RefList.tsx` (add/edit/archive for one kind), `pages/Reference.tsx` at `/reference/:kind`. Extra fields per kind (camera `fixed_lens`/`notes`, film `type`/`box_iso`) live in `RefForm` inside `RefList.tsx`. Log screen (Task 2.4): `/` is `pages/LogRoll.tsx` = `components/RollForm.tsx` (create and edit; all draft values are strings, `draftToBody` converts) + `components/RecentRolls.tsx`. `lib/setup.ts` remembers camera, lens, format and developer in localStorage (`darkroom.setup`) and `applyCameraDefaults` fills lens/format from the camera's last roll; `lib/stops.ts` mirrors the backend stops maths for the live display (the server value is authoritative). After a create the setup fields and date are kept and film, EI, dev time, subject and notes cleared. `src/test/mockApi.ts` is an in-memory fetch mock for screen tests. `RefSelect.onChange(id, item)` also passes the full item (used to read a film's box ISO). Stock screens (Task 3.5): `api/stock.ts` (types and hooks for stock, movements, bulk rolls and settings; **writes invalidate `stock`, `movements` and `bulk`, roll writes also `stock`**; `insufficientStock(error)` reads the 409 body), `components/ErrorNote.tsx` (**use it to show any write error**: a refused stock write also gets "Record a recount" and "Record a purchase" links to `/stock?recount=film:format` and `/purchases?film=..&format=..`), `components/BulkMeter.tsx`, `lib/format.ts` (exact `parsePounds`/`parseMetres` into pence/mm, never floats). Pages: `Stock` (individual rolls grouped by film type and zero rows hidden by default, film-name search and type filter for rolls and bulk spools, format filter for individual rolls, roll sorting by name or quantity, recount form, spool meters with sorting by remaining length), `Purchases` (Bought / Loaded from bulk / Given away, recent entries with edit and delete), `SettingsBulk` (leader, pitch, timezone, edit and delete spools; **new spools are added from the Purchases screen's "Bulk spool" mode**, using the shared `components/SpoolForm.tsx`, whose `simple` mode hides "used before tracking" and "finished") under `SettingsLayout` tabs at `/settings` and `/settings/bulk`. `ApiError.body` holds the parsed error JSON. Tests render with `renderApp` (`src/test/render.tsx`: query client + MemoryRouter) and the in-memory `installMockApi({ handler })` for routes it does not know. Styles are plain CSS in `src/styles/global.css` (44px touch targets, 16px inputs, dark theme only since the field-notebook redesign; `src/styles/touch.test.tsx` checks the 44px and 16px rules against the real stylesheet on the log, purchases and stock screens).
- `Dockerfile` (frontend build, then python:3.12-slim runtime; runs `alembic upgrade head` then uvicorn with `--proxy-headers`), `compose.yaml` (`app`, `db`, no `ports:`, external network from `CLOUDFLARED_NETWORK`), `.env.example`. Check with `docker compose --env-file .env.example config` and `docker compose build`.
- Backups (Task 7.2): the `backup` compose service (`ops/backup/`, `postgres:16` image so `pg_dump` matches the server) runs `run.sh` (dump at start-up, then daily at `BACKUP_HOUR` UTC), `backup.sh` (dump to a temp file, `pg_restore --list` check, move to `/backups/darkroom-YYYYMMDD.dump` without overwriting, delete dumps older than `RETENTION_DAYS` but always keep the newest 3) and `restore.sh <dump> <db> [--replace]` (restores into a temporary database and only then renames it into place, so a failed restore changes nothing; `--replace` keeps the old database as `<db>_old_<time>`; prints `rolls` and `stock_movements` counts). The service has `init: true` so stop is prompt. `ops/backup/selftest.sh` exercises all of it against a throwaway Postgres and runs in the CI `image` job. `./backups` is gitignored.
- CSV export (Task 7.1): `services/export.py` `export_table(session, table)` (CSV text, header first, rows by primary key) and `api/export.py` (`GET /api/export` lists names, `GET /api/export/{table}.csv`, `films:read`). **`EXPORT_TABLES` is an allowlist**: a new table is private until added there; secrets, OAuth, users, the import ledger and `alembic_version` are not on it. Text cells starting with `= + - @` (after NFKC, so full-width forms count) get a leading apostrophe (formula safety); numbers are untouched. CSV responses send `Cache-Control: private, no-store` because Cloudflare caches `.csv` by default and would otherwise serve private data without asking the app. The API reads the whole table before responding (small data), so the session lifetime stays simple. Settings page has the download links.
- Auth (Task 1.1): `auth/principal.py` (`Principal`, `current_principal` dependency; write implies read), `auth/sessions.py` (Postgres sessions, cookie `darkroom_session` holds a random id, only its SHA-256 is stored; 30-day sliding, 90-day cap), `auth/csrf.py`, `auth/google.py` (Authlib + joserfc OIDC with PKCE/state/nonce behind the `OIDCProvider` protocol), `api/auth.py` (`/api/auth/login|callback|logout`, `/api/me`). **Protect every new endpoint with `Depends(current_principal)`**: it enforces CSRF (Origin + `X-CSRF-Token`) for cookie-authenticated unsafe methods. The browser gets its CSRF token from `GET /api/me`.
- Tokens (Task 1.2): `Principal` lives in `auth/identity.py` (re-exported from `auth/principal.py`). `current_principal` accepts `Authorization: Bearer drk_...` (no CSRF) or the session cookie; a bad Bearer never falls back to the cookie. **Use `Depends(require_scope(READ|WRITE))` on data endpoints** (write implies read; sessions hold both). Token management (`/api/tokens`) uses `require_session_principal`, so a token cannot mint or revoke tokens. PATs: `drk_` + random, only SHA-256 and an 8-char prefix stored, revoke sets `revoked_at` (rows kept), `last_used_at` updated on every use. `auth/verifier.py::verify_bearer` is where OAuth access tokens join in Phase 6. Test helpers: `scoped` fixture adds `/api/_test/read|write`, `make_token` creates a PAT via the API.
- Reference data (Task 2.1): `models/reference.py` (`NamedItem` abstract base: case-insensitive `citext` unique `name`, `archived_at`; `Format, Camera, Lens, Developer, Filter, Film`, `AppSettings` single-row `settings` table, `RefKind`). `services/reference.py` (`list_items/create_item/update_item/archive_item/unarchive_item`; raises `NotFoundError`/`DuplicateNameError`, which the API maps to 404/409). `api/reference.py` registers the same five routes per kind from a `Spec` list, so adding a field means editing `schemas/reference.py` and the model only. Reads need `films:read`, writes `films:write`. Items are archived, never deleted. Migration 0004 seeds formats 35mm/120/110 and the settings row. PATCH treats null as "unchanged" for non-nullable columns; `exclude_unset` decides which fields are touched.
- Rolls (Task 2.3): `models/rolls.py` (`Roll`, relationships eager-joined; year, month, film type, box ISO and stops are **derived in `RollOut`, never columns**), `services/units.py` (pure `stops_vs_box`, `format_stops`), `services/rolls.py` (`create/update/delete_roll`, `list_rolls(filters, page) -> (rows, total)`, `last_roll_for_camera`), `api/rolls.py` (`/api/rolls`, `/api/cameras/{id}/last-roll`). EI and dev time are `Decimal` in and out as JSON numbers. Referenced items must exist and not be archived unless unchanged on that roll (so old rolls keep archived gear). `lens_id: null` means N/A. List responses are `{items, total, limit, offset}`, newest `dev_date` first. Stock checks come in Task 3.3 and must hook into `create_roll`/`update_roll`/`delete_roll`.
- Bulk maths and settings (Task 3.1): `services/units.py` has `cassette_mm` and `bulk_derived` (pure, integer-only; `left_mm` may be negative, `exposures_left` floors at 0, `cost_per_36_pence` rounds half up and is None when unpriced). `services/settings.py` + `api/settings.py`: `GET|PATCH /api/settings` (leader 1-10000 mm, pitch 1-1000 mm, valid IANA timezone). Services that need the leader/pitch call `get_settings(db)`; a bulk load stores its own `metres_mm` snapshot, so changing settings never rewrites history, but `exposures_left` and `cost_per_36_pence` always use the current settings.
- Stock (Task 3.2): `models/stock.py` (`StockMovement` with one CHECK per kind so other kinds' fields must be null; `BulkRoll`, API arrives in 3.4; `stock_levels` SQL view = movements minus rolls with `counts_against_stock`, queried through the `stock_levels` table object). `services/stock.py`: `record_purchase/bulk_load/given_away/opening/adjustment`, `create/update/delete_movement`, `get_stock`, `current_stock`. Rules: `rolls` is **signed** in the API (given away is negative); `bulk_load` takes film from the spool and is always the 35mm format, snapshots `metres_mm` from the settings at that moment (editing its rolls/exposures re-snapshots) and may exceed the spool; an adjustment stores the delta and `counted_to`, rejects a no-op, and only its date and notes can be edited later (`EDITABLE` map). **Non-negative stock (Task 3.3):** `lock_pairs` (advisory lock per film/format, sorted order, returns stock under the lock) then flush then `assert_non_negative` (raises `InsufficientStockError`, which `main.py` turns into a 409 with `code`, `film_id`, `format_id`, `available` so the UI can offer a recount). It runs in create/update/delete of rolls and in given-away, edits and deletes of movements; only writes that can *lower* a pair are checked (purchases, openings, bulk loads, roll deletes, and edits that do not reduce stock never fail, so they can repair a shortfall), and adjustments lock first because their delta is worked out under the lock. **Any new write path that can reduce stock must follow this lock, write, flush, assert, commit order.** Tests that create counted rolls need stock first (`tests/rolls/conftest.py` stocks everything automatically). `reset_db` (tests) leaves `stock_levels` alone since it is a view.
- Stocktake (#67): `POST /api/stocktakes` (`services/stock.py` `record_stocktake`, `schemas/stock.py` `StocktakeIn`) takes several counts, each with the `expected` balance the user reviewed, plus a client-made `batch_id`. It locks every pair, and if any pair's stock differs from `expected` it writes nothing and returns 409 `code: stock_changed` with the rows (so the UI flags them). Otherwise it records only the differences as `adjustment` movements stamped with `count_batch_id` (migration 0009); a retry of the same `batch_id` returns the same movements (`replayed: true`) and writes nothing. UI: `components/Stocktake.tsx` (count, review differences, apply) opened from the Stock page's "Stocktake…" button. Stock page also has filters and sorting (name, type, format; rolls and bulk spools sorted separately); the default view is still grouped by film type.
- Bulk rolls (Task 3.4): the `BulkRoll` model lives in `models/stock.py` next to `StockMovement`. `services/bulk.py` returns `BulkRollOut` with `cassettes_loaded`, `used_mm` (= `used_before_mm` + the stored load snapshots), `left_mm` (may be negative), `exposures_left` and `cost_per_36_pence` from `bulk_derived` and the *current* settings. `/api/bulk-rolls` CRUD: label is case-insensitive unique (409), a spool's film cannot change once it has loads (409), a spool with loads cannot be deleted (409; mark it `finished` instead), and loads are recorded through `POST /api/stock-movements` with `kind: bulk_load`. After commit the service `expunge_all()`s and reloads so the joined film is fresh.
- API docs: FastAPI's public `/docs`, `/redoc`, `/openapi.json` are disabled in `create_app`; `api/docs.py` serves them at `/api/docs`, `/api/redoc` and `/api/openapi.json` behind `films:read` (a session cookie or a bearer token). Do not re-enable the defaults: they list every endpoint without sign-in.
- Sheet import (Phase 4): `importer/parse.py` turns the sheet's CSV exports into plain rows with **names, not ids** (`parse_tracker/films/lists/bulk/purchases/dev_time_refs`, `parse_all(folder)`); columns are found by header name with aliases, all problems in a file are reported together as `ParseError.problems`. Exact money and lengths only (`parse_pence`, `parse_length_mm`). The layouts are assumptions from the spec, **not yet verified against the real exports**: read `docs/notes/sheet-import-assumptions.md` before changing them. Fixtures in `backend/tests/importer/fixtures/` are synthetic; the real `import/` folder is gitignored and must never be committed.
- Sheet loader (Task 4.2): `importer/load.py` `load_all(session, ParsedSheet, actor_user_id) -> LoadReport` (`parse_all` now returns `ParsedSheet`). Names are checked first against the database plus the sheet's own Lists/Films tabs; any unknown camera, lens, film, developer, filter or format raises `UnknownNames` (all listed, nothing written). Then Lists/Films create reference items, then bulk spools, rolls (`counts_against_stock = dev_date > 2026-11-22`), opening movements and purchases, all in one transaction. `import_ledger` (migration 0007) keys every row by `(tab, fingerprint, occurrence)`: identical rows are each kept, a rerun inserts nothing, and a row added later is picked up. Dev time reference rows load into `dev_time_refs` (tab `dev_times`; a reference already entered by hand for the same film, EI and developer is kept).
- Import command (Task 4.3): `python -m app.importer.cli <folder> [--dry-run]` (`importer/cli.py` `import_folder`, `importer/reconcile.py`). Loads with `load_all(commit=False)`, reads the figures back from the database (`reconcile(imported_only=True)`: only records the ledger says came from the sheet, so rolls already logged in the app do not disturb it; found on the first real run, which had one 110 roll in the app) and commits only if they match `Expected` (117 rolls, 60/57 per year, 61 x 35mm, 88 x 120, Bulk 1 7300 mm); otherwise rolls back (exit 1; bad input exit 2). Needs one user to exist (sign in once). Verified on 2026-11-23 against the real exports in a scratch Postgres (matched, rerun inserted nothing). `parse_all` also accepts Google's `<Spreadsheet> - Tracker.csv` names.
- Dev times (Task 5.1): `models/devtimes.py` `DevTimeRef` (unique film, EI, developer; migration 0008), `services/devtimes.py` `grouped_dev_times(db, film_id, ei, developer_id)` (groups logged roll times by film + EI + developer, newest first, null times left out, with the hand-entered reference attached; a reference with no rolls still shows) and ref CRUD (duplicate is a 409, unknown film or developer a 422), `api/devtimes.py` (`GET /api/dev-times`, `/api/dev-time-refs` CRUD; reads `films:read`, writes `films:write`). Frontend: `api/devtimes.ts`, `pages/DevTimes.tsx` at `/dev-times`.
- Stats (Task 5.2): `services/stats.py` aggregates roll counts and spend in Postgres. `api/stats.py` serves `GET /api/stats`, `/api/stats/camera-idle` and `/api/stats/spend` with `films:read`. The configured timezone determines today's date. Future cumulative points are null.
- Low stock (#68): `services/stats.py` `low_stock(db, today)` behind `GET /api/stats/low-stock` (`films:read`). Per film and format, using the current `stock_levels` balance (0 when there is no row, so zero-stock favourites appear): at least `MIN_ROLLS` (3) rolls with `dev_date` in the last `WINDOW_DAYS` (90, today included) and `balance * 90 <= 30 * rolls` (no more than 30 days of stock at that pace; integer maths). Only developed rolls count (purchases and recounts are not usage); archived films and formats are left out; `days_of_stock` rounds down; `on_bulk_spool` marks 35mm pairs whose film has an unfinished bulk spool (the balance only counts loaded cassettes, so the fix may be loading, not buying). Frontend: `useLowStock` (key `["stock","low"]`, so stock and roll writes refresh it) and the "Running low" panel at the top of `pages/Stock.tsx`, which states rolls left, rolls developed and days of stock.
- Dashboard (Task 5.3): `pages/Dashboard.tsx` at `/dashboard` (route **lazy-loaded** so Chart.js, 61 kB gzip, stays out of the main bundle), `api/stats.ts`, `components/MonthlyChart.tsx` (Chart.js bar + running-total line, only the used pieces registered, colours read from the CSS variables; jsdom has no canvas so tests `vi.mock` it; plots the chosen year and the previous one, and rebuilds when the system theme changes) and `components/Breakdown.tsx` (CSS bars scaled to the largest row). The year selector defaults to the server's current year (no `year` param), stays mounted when a request fails, and only offers years 1900-2200 (what `/api/stats` accepts). Each panel shows its own loading and error (with retry).
- OAuth and MCP (Phase 6): `auth/oauth_server.py` holds registration, code issue, `exchange_authorization_code`, `refresh_tokens` (rotation within a family; reuse of a rotated token revokes the family) and `revoke_token`; `api/oauth.py` has the routes (`/oauth/register|authorize|authorize/consent|token|revoke`). Access tokens `dro_` (3600s), refresh `drr_` (30 days), hashes only. `auth/verifier.py` `verify_bearer(db, raw, audience=None)`: PATs work on `/api` and `/mcp`; **OAuth tokens are bound to `<base>/mcp` and are rejected on `/api`**. `DarkroomTokenVerifier` plugs into `MCPServer` (`mcp/server.py` `build_mcp(settings, engine_getter)`, `AuthSettings` with `required_scopes=[films:read]`; the verifier adds read when a token has write). Our protected-resource route is inserted *before* the SDK's so it lists both scopes. Tools: `mcp/read_tools.py` and `mcp/write_tools.py` are adapters over services (`mcp/context.py`: `caller(scope)`, `tool_session`, `resolve_ref` accepts a name or id); service refusals become `ToolError`s; **no delete tools**; every successful write calls `services/audit.record_audit` (`audit_events`, migration 0011, `GET /api/audit-events`, Activity page). MCP tests live in `tests/mcp/` (`mcp_env`, `mcp_session`, `call_tool`, `seed` in its conftest).
- Test fixtures: `gear` (one of each reference item, ids) and `roll_body(gear, **over)` live in `tests/support.py`; `authed` (signed-in session client with CSRF/Origin headers preset) and `bearer_client(*scopes)` (cookie-less client holding a fresh PAT), both in `tests/support.py`.
- The model is `UserSession` (table `sessions`). Login-in-progress state (state/nonce/verifier) is a short-lived signed cookie `darkroom_oidc`, not a DB row.
- Tests: `migrated_db` (session fixture) applies migrations once; `client` calls `reset_db` first (truncates every table except `users`, `formats`, `settings`; deletes users; removes non-seed formats; resets settings), so **seed data survives between tests and must never be truncated with CASCADE through `users`**. Add new seeded tables to `KEEP_TABLES`. Auth tests replace `app.state.oidc` with a fake (`tests/auth/conftest.py`). Tests that downgrade must upgrade again.
- Tests that hit `/mcp` need `LifespanManager` (see `test_mcp_mount.py`).
- MCP OAuth discovery (Task 6.1) lives in `auth/oauth_server.py`. Both metadata documents use the same issuer derived from `PUBLIC_BASE_URL`. The SDK route factory provides the protected-resource document before bearer enforcement in Task 6.4. Migration 0010 adds the OAuth client, code and token tables.
- OAuth registration and consent (Task 6.2) live in `api/oauth.py` with validation and persistence in `auth/oauth_server.py`. The public registration budget is enforced in Postgres. Authorization resumes through the existing Google callback, which can return only to the local OAuth authorization route. Consent uses a signed form bound to the browser session and checked against the request Origin. Codes are hashed, expire after 60 seconds, and carry the exact redirect URI, PKCE challenge and MCP resource. Task 6.3 consumes each code once.
- Tests run on one session-scoped event loop (see `pyproject.toml`)

## Conventions

- Money is integer pence, lengths integer millimetres. No floats for either.
- No SQLite, ever. Tests use real Postgres.
- One service layer (`services/`) owns derived figures and invariants; REST and MCP are thin adapters.
- External URLs come from `PUBLIC_BASE_URL`, never request headers.
- Work follows the plan's steps (TDD), one commit per task with the message given in the issue.

## Workflow (GitHub issues and PRs)

- Every plan task is a GitHub issue (`gh issue list`, `gh issue view N`). Work from the issue: follow its steps in order.
- One branch and one PR per task (or per tightly related group), branched from an up-to-date `main`, named like `task-1.1-google-login`. Never push to `main` directly.
- Keep issues current as you go: tick completed steps in the issue body, comment on findings, deviations from the plan, or blockers, and comment with the commit/PR when done.
- PR body links the issue with `Closes #N` (use `Refs #N` if a manual step remains, and leave the issue open until it is verified). Issues close when the PR merges.
- If the work changes how things run or are laid out, update this file, the README and `docs/notes/` in the same PR.
- Run `uv run pytest`, ruff and mypy (plus `npm run typecheck` for frontend work) before opening the PR.
- CI (`.github/workflows/ci.yml`) runs three jobs on every PR and push to `main`: `backend` (ruff, format check, mypy, pytest), `frontend` (typecheck, tests, build) and `image` (docker build, import `app.main`, compose has no `ports:`). GitHub branch protection is unavailable (private repo, free plan), so this is by convention: never push to `main`, and only merge a PR once all three jobs are green. Any deploy workflow must itself wait for CI.
